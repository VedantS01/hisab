# Format Generalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Parse any Indian bank statement via a silent, self-validating generic engine (bundled specs + conservative inference + balance-chain proof), open the `Source` model to arbitrary string ids without disturbing existing content hashes, add an email-based format-request flow, ship an expanded india-default ruleset, and add a polite on-device rule-suggestion prompt.

**Architecture:** All logic lands in the pure-Swift `HisabCore` package (TDD via `swift test` on macOS); the SwiftUI app layer only wires resolver results and two small UI surfaces (unsupported-format sheet, boot-time suggestion prompt). Bank correctness rests on one invariant everywhere: a parse is accepted only when the running-balance chain closes to the paisa.

**Tech Stack:** Swift 6 (HisabCore: Foundation/CryptoKit/PDFKit/Compression only), SwiftUI + SwiftData app generated by xcodegen, XCTest.

**Spec:** `docs/superpowers/specs/2026-09-16-format-generalization-design.md`

## Global Constraints

- `FormatSpec` stays purely declarative JSON — no expression language, no eval-like fields.

- Nothing unvalidated enters the ledger: chain must close exactly or the import fails into the request flow. Never a partial or best-guess import.
- Test fixtures are synthetic, always. Never commit or embed real statements (`samples/` stays gitignored).
- All calendar math in IST (`YearMonth.istCalendar`); money is integer paise (`Int64`), amounts parsed via `Money.signedPaise(fromDecimalString:)`.

```swift
/// Statement sources. The five original ids are frozen (they live inside stored
/// content hashes); new banks/apps use open ids like "bank:sbi" or "upi:phonepe".
public struct Source: RawRepresentable, Codable, Hashable, Sendable, Identifiable {
    public let rawValue: String
    public init(rawValue: String) { self.rawValue = rawValue }
    public var id: String { rawValue }

    public static let gpay = Source(rawValue: "gpay")
    public static let paytm = Source(rawValue: "paytm")
    public static let bhim = Source(rawValue: "bhim")
    public static let hdfc = Source(rawValue: "hdfc")
    public static let idfc = Source(rawValue: "idfc")
    /// Sources with first-party parsers; drives pickers, filters, and grid columns.
    public static let builtIn: [Source] = [.gpay, .paytm, .bhim, .hdfc, .idfc]

    public var kind: SourceKind {
        switch rawValue {
        case "gpay", "paytm", "bhim": return .paymentApp
        default: return rawValue.hasPrefix("upi:") ? .paymentApp : .bank
        }
    }

    public var displayName: String {
        switch rawValue {
        case "gpay": return "Google Pay"
        case "paytm": return "Paytm"
        case "bhim": return "BHIM UPI"
        case "hdfc": return "HDFC Bank"
        case "idfc": return "IDFC First Bank"
        default:
            let slug = rawValue.split(separator: ":").last.map(String.init) ?? rawValue
            return slug.count <= 4 ? slug.uppercased() : slug.capitalized
        }
    }
}
```

Note: `RawRepresentable where RawValue: Codable` supplies single-value string coding automatically — do not write manual Codable code. Keep `SourceKind` as is.

```swift
static func splitCSVLine(_ line: Substring) -> [String] {
    var cells: [String] = []; var current = ""; var inQuotes = false
    for ch in line {
        switch (ch, inQuotes) {
        case ("\"", _): inQuotes.toggle()
        case (",", false): cells.append(current); current = ""
        default: current.append(ch)
        }
    }
    cells.append(current)
    return cells.map { $0.trimmingCharacters(in: .whitespaces) }
}
```

### Task 5: `ColumnMapping` + `ChainInterpreter` (the validator)

**Files:**
- Create: `HisabCore/Sources/HisabCore/GenericBank/ChainInterpreter.swift`
- Test: `HisabCore/Tests/HisabCoreTests/ChainInterpreterTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public struct ColumnMapping: Equatable, Sendable {
      public var date: Int
      public var narration: Int
      public var reference: Int?
      public var debit: Int?        // separate-debit-column convention
      public var credit: Int?       // separate-credit-column convention
      public var amount: Int?       // single amount column
      public var drcr: Int?         // "DR"/"CR" qualifier column for `amount`
      public var balance: Int
      public var dateFormat: String // en_US_POSIX, IST
      public init(...)              // memberwise, all defaulted to nil where optional
  }
  public enum ChainOutcome: Sendable, Equatable {
      case validated([ParsedTransaction])
      case broken(rowIndex: Int, detail: String)
  }
  public enum ChainInterpreter {
      public static func interpret(rows: [[String]], mapping: ColumnMapping) -> ChainOutcome
  }
  ```
- Consumes: `Money.signedPaise(fromDecimalString:)`, `SyntheticRef.make`, `ParsedTransaction`, `YearMonth.istCalendar`.

Semantics (this is the correctness core — implement exactly):
- `rows` are body rows only (header/furniture already stripped by callers).
- Per row: parse date (DateFormatter, `mapping.dateFormat`, IST, POSIX); read balance via `Money.signedPaise`. Amount + direction candidates by convention: debit/credit columns (exactly one non-empty; its column names the direction), amount+drcr (`DR`→debit, `CR`→credit, case-insensitive), signed amount (negative→debit), or unsigned amount alone (direction unknown → recovered from the chain).
- Chain rule from row 2 onward: `prev − amount == bal` ⇒ debit, `prev + amount == bal` ⇒ credit. When the columns also assert a direction, the chain must AGREE — disagreement is `.broken` (this double-checks even explicit debit/credit columns).
- Row 1 has no `prev`: if its direction is underdetermined (unsigned amount, no drcr), run the whole interpretation twice (first row debit, then credit) and return whichever validates; both validating with different outputs ⇒ `.broken(rowIndex: 0, detail: "ambiguous opening direction")`.
- Reference: cell text if `mapping.reference` set and non-empty, else `SyntheticRef.make(balancePaise:date:amountPaise:)`.
- Counterparty = narration cell; `ParsedTransaction(date:amountPaise:direction:counterparty:reference:narration:)` with amountPaise always positive.
- Any unparseable date/amount/balance ⇒ `.broken` with the row index and offending cell in `detail`. Never skip a body row.

  ```swift
      public var id: String                       // "sbi-xlsx"
      public var sourceID: String                 // "bank:sbi"
      public var bankName: String                 // "State Bank of India"
      public var provisional: Bool
      public var headerPatterns: [String: String] // role → case-insensitive regex over a header cell

                                                  //        amount, drcr, balance
      public var furniturePatterns: [String]      // whole-row regexes to drop from the body
      public var dateFormats: [String]            // tried in order; first that parses every body date wins
      public var signConvention: String           // "debitCredit" | "signedAmount" | "amountDRCR" | "unsignedChain"
  ```

Executor algorithm: scan rows top-down for the first row where every REQUIRED role regex (`date`, `narration`, `balance`, plus the convention's amount roles) matches a distinct cell (case-insensitive `NSRegularExpression` or Swift `Regex(...).ignoresCase()`); that's the header — build the `ColumnMapping` from the matched cell indices. Try `dateFormats` in order; pick the first where every body row's date cell parses; none ⇒ `.broken`. Then delegate to `ChainInterpreter`. ### Task 8: `ColumnInference` (conservative)

**Files:**
- Create: `HisabCore/Sources/HisabCore/GenericBank/ColumnInference.swift`
- Test: `HisabCore/Tests/HisabCoreTests/ColumnInferenceTests.swift`

**Interfaces:**
- Produces:
  ```swift
  public enum ColumnInference {
      public struct Result: Sendable { public let mapping: ColumnMapping
                                       public let transactions: [ParsedTransaction] }
      /// Exactly-one-validating-interpretation or nil. Never guesses.
      public static func infer(table: NormalizedTable) -> Result?
  }
  ```
- Consumes: `ChainInterpreter`, `ColumnMapping`.

Algorithm:
1. Header detection: first row containing ≥2 cells matching `(?i)date|narration|particular|description|remarks|debit|credit|withdraw|deposit|amount|balance` and whose cells do NOT parse as dates. Rows above it are furniture. If none found, treat row 0 as start of body (headerless TXT case).
2. Body = rows below with ≥3 non-empty cells; drop rows where no cell parses as a date under any candidate format.
3. Candidate columns: date columns (≥90% of body rows parse under one of the formats `["dd/MM/yyyy","dd/MM/yy","dd-MM-yyyy","dd MMM yyyy","yyyy-MM-dd","dd-MMM-yy"]`), numeric columns (≥90% parse via `Money.signedPaise`, after stripping trailing `(Cr)|(Dr)|CR|DR` markers), drcr columns (≥90% of cells case-insensitively `dr` or `cr`).
4. Enumerate mappings: for each date column × each numeric column as balance × each convention — (a) every ordered pair of remaining numeric columns as (debit, credit) where the two are never both non-empty; (b) each remaining numeric as signed amount; (c) each remaining numeric + each drcr column; (d) each remaining numeric as unsigned-chain amount. Narration = the non-numeric, non-date column with the longest average cell text; reference = a remaining mostly-alphanumeric column if present, else nil.
5. Run `ChainInterpreter.interpret` for every candidate (bounded: tables have ≤ ~12 columns). Collect `.validated` outcomes; de-duplicate by their transaction lists. Exactly one distinct outcome ⇒ return it; zero or several ⇒ nil.

- [ ] **Step 1: Failing tests** — (a) SBI-shaped table with header infers and validates, recovering the same txns as an explicit mapping; (b) column-shuffled variant of the same table still infers identically; (c) DR/CR-suffix variant infers; (d) an ambiguous table (two numeric columns that can each close a chain — construct with amounts equal to balance deltas in both columns) returns nil; (e) a table with a broken chain returns nil; (f) headerless TXT-style table infers. Reuse one balance-consistent row set across tests.
